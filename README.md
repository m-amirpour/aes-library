# aes-library

AES-256-CTR with runtime hardware acceleration. Uses AES-NI on x86-64 or ARMv8 Crypto Extensions on AArch64 when available, and falls back to a portable software implementation otherwise. The same binary works on both — no recompile required.

---

## What's in the box

- **Core**: Encrypt/decrypt `std::vector<std::byte>` using AES-256-CTR.
- **Key generation**: Cryptographically secure random keys (OS CSPRNG – `BCryptGenRandom` on Windows, `/dev/urandom` on POSIX).
- **Storage**: Custom binary container format that includes a version marker and the nonce/IV alongside the ciphertext. Keys and ciphertext are stored in **separate files**.
- **Bonus extras** (optional, built if enabled):
  - Template API for encrypting trivially‑copyable structs directly.
  - C ABI shared library (`aes_capi`) with a Python `ctypes` example.
  - GoogleTest unit tests (25+ tests covering round‑trips, NIST vectors, and dispatch paths).

---

## Design Overview

### Hardware / Software Dispatch

- At runtime, the library checks the CPU capabilities:
  - **x86-64**: uses `__cpuid` (via `<intrin.h>`) to test the AES-NI bit (`CPUID.ECX: bit 25`).
  - **AArch64**: uses `IsProcessorFeaturePresent(PF_ARM_V8_CRYPTO_INSTRUCTIONS_AVAILABLE)` on Windows, or `getauxval(AT_HWCAP)` on Linux.
- The chosen path (hardware or software) is **observable** for testing (`crypto::using_hardware()`), but normal callers don't need to care – it's entirely transparent.
- Both paths produce **bit‑identical** output for the same key/nonce/plaintext, verified by the unit tests.

### Nonce Strategy

- Uses a **96‑bit nonce** (12 bytes) generated by the OS CSPRNG.
- Combined with a **32‑bit counter** (starting at `1`) to form the full 128‑bit CTR initial value.
- The library **refuses** to encrypt more than `2³²` blocks (≈ 64 GiB) with a single key/nonce pair, preventing counter overflow and complying with NIST SP 800‑38A recommendations.
- The nonce is stored alongside the ciphertext in the container format.

### On‑Disk Container Format

All encrypted blobs follow a simple, versioned binary format:

| Offset | Size (bytes) | Field          | Description                                      |
|--------|--------------|----------------|--------------------------------------------------|
| 0      | 1            | `version`      | Format version (currently `0x01`).               |
| 1      | 12           | `nonce`        | 96‑bit nonce (CSPRNG‑generated).                 |
| 13     | N            | `ciphertext`   | The AES‑CTR encrypted payload (same length as plaintext). |

- The version byte allows the format to evolve later while maintaining backward compatibility.
- Keys are stored **separately** – never in the same file as the ciphertext.

### Secure Key Material Handling

- All key buffers are **zeroed** as soon as they are no longer needed using `SecureZeroMemory` (Windows) / `explicit_bzero` (POSIX) – compiler‑safe.
- Memory containing keys is optionally **locked** (`VirtualLock` / `mlock`) to prevent paging to disk.
- The library minimises copies of key material; the key lives in a dedicated `SecureVector` that zeroes on destruction.

## Building

**Prerequisites**: CMake 3.20+ and a C++17 compiler (MSVC 2019+, GCC 9+, Clang 10+).

> GoogleTest is fetched automatically on first configure via `FetchContent` – no manual installation needed.

### Linux (Fedora / RHEL)

```bash
sudo dnf install gcc-c++ cmake git
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

### Linux (Debian / Ubuntu)

```bash
sudo apt install build-essential cmake git
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

### Windows (MSVC)

**Prerequisites**:
- [Visual Studio](https://visualstudio.microsoft.com/) (2022 or 2026) with the **"Desktop development with C++"** workload.
- [CMake](https://cmake.org/download/) (3.20+) – make sure it's added to your `PATH` during installation.
- Git (for FetchContent to download GoogleTest).

You have three options:

#### Option 1: Command Line (Developer Command Prompt)

1. Open the **Developer Command Prompt for VS 2026** (or 2022) from the Start Menu.
   > This sets up the correct environment variables for `cl.exe` and the Windows SDK.
2. Navigate to your project root and run:
   ```powershell
   cmake -B build -G "Visual Studio 18 2026" -A x64
   ```
   > *If you're using VS 2022, use `-G "Visual Studio 17 2022" -A x64` instead. You can also omit `-G` entirely – CMake will auto-detect your installed VS version.*
3. Build the project:
   ```powershell
   cmake --build build --config Release
   ```
   > For a Debug build, use `--config Debug`.

#### Option 2: PowerShell / CMD (without Developer Prompt)

If you don't want to use the Developer Prompt, you can specify the generator explicitly:
```powershell
cmake -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

#### Option 3: Visual Studio IDE

1. Open Visual Studio and select **"Open a local folder"** – point it to the project root.
2. Visual Studio will detect the root `CMakeLists.txt` and configure automatically.
3. In the top toolbar, set the configuration to `Release` (or `Debug`) and the architecture to `x64`.
4. Build the `aes_harness` target directly from the IDE (right‑click → Build).

#### Build Options (Windows)

Disable optional components by passing these flags during the **first** CMake configure:
```powershell
cmake -B build -DAES_BUILD_TESTS=OFF -DAES_BUILD_BINDINGS=OFF
```
Then rebuild normally.

#### Troubleshooting Windows Builds

| Issue | Fix |
|-------|-----|
| **`bcrypt.h` compiler errors (C4430, C2059)** | This is a known Windows 11 SDK (10.0.26100.0) + C++17 conformance bug. The library already includes a workaround in `platform_windows.cpp` (`_Return_type_success_` undef). Make sure you have the latest Windows SDK or apply the fix if you see it. |
| **`__cpuid` not found** | Ensure `<intrin.h>` is included (it is). This requires the Visual Studio C++ tools. |
| **CMake doesn't find Visual Studio** | Open CMake from within the **Developer Command Prompt**, or specify the generator explicitly (`-G "Visual Studio 18 2026"`). |
| **`bcrypt.lib` linker errors** | The CMake script links `bcrypt` automatically. If you see `LNK1104: cannot open bcrypt.lib`, ensure your Windows SDK is installed correctly. |
| **`ctest` shows no tests** | Use `ctest -C Release` (Windows requires the `-C` flag to match the build configuration). |

## Running

### Test Harness (End‑to‑End)

The `aes_harness` executable performs a full round‑trip:

1. Generates a sample plaintext file.
2. Generates a secure AES‑256 key.
3. Encrypts the file contents and saves the ciphertext (and key separately).
4. Loads the ciphertext and key back from disk.
5. Decrypts and compares to the original.

Run it from the project root:

**Linux / macOS:**
```bash
./build/aes_harness
```

**Windows:**
```powershell
.\build\Release\aes_harness.exe
```
> If you built in Debug mode, the path is `.\build\Debug\aes_harness.exe`.

The harness will print which code path was used (`Hardware (AES-NI)` or `Software fallback`) and report `PASS` / `FAIL`.

### Unit Tests

After building, run the test suite via CTest:

**Linux / macOS:**
```bash
cd build
ctest --output-on-failure
```

**Windows:**
```powershell
cd build
ctest -C Release --output-on-failure
```
> The `-C Release` flag is **required** on Windows to tell CTest which configuration to test.

### Python Demo (C ABI Bindings)

If `AES_BUILD_BINDINGS` is `ON`, the shared library (`aes_capi`) is built. Run the Python example:

```bash
python3 bindings/python/example.py
```
